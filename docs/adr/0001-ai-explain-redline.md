# ADR 0001: AI 解读层采用「LLM 只转录 + 双道守卫」红线范式

- 状态：Accepted（2026-11-02）· **修订 1（2026-11-02，交叉对抗审查后）**
- 关联 Spec：`docs/specs/ai-explain.md`

## 背景

本项目核心纪律：系统唯一有证据的口径只有类别先验，短名单/终选/综合判断等
第二结论源已全部删除（AGENTS.md）。引入 LLM 的最大风险是制造第二个结论源。

## 决策

1. **LLM 不产生任何数字与判断**：服务端纯函数从 D1 快照组装带 ID 的素材数组
   （缺字段写「暂无数据」），LLM 只把素材转成自然语言。
2. **守卫只有两道，且都是确定性的**：
   - 素材确定性组装（不信任任何模型输出作为事实源）；
   - 输出词表扫描（建议动词命中 → 整体替换为拒答文案）。
   无自由文本输入 → 「拦截用户越界提问」这道闸在结构上不需要。
3. **AI 输出不入任何计算路径**：不写 recommendations、不进排序/过门，
   仅内存缓存用于去重。
4. **每个响应强制带 `label: "仅解读，非投资建议"`**，由服务端保证。

## 修订 1：词表守卫的承诺降级（审查 A / P1-1，实测证实）

初版实现用**逐字正则**匹配，交叉对抗审查实测 **8/8 平凡变体可绕过**：
一个全角冒号（`建议：买入`）、一个词内空格（`建 议买入`）、一句英文（`buy zone 17.8`）、
`目标位`/`合理价`/`看多`/`轻仓` 等同义表达，均可整体逃逸。

**处置**：守卫改为**归一化 + 槽位匹配**（去空白/全角转半角/大写小写 → 动作槽位与副词共现判定），
并把上述逃逸例句固化为回归（`worker/test/guard.test.ts`，10 例必须拦截 + 5 例不得误杀）。

**但残余风险仍在，故本 ADR 明文降级承诺**（不再声称「守卫充分」）：
- 归一化 + 槽位挡得住**已知平凡变体**，挡不住：① 槽位表外的说法（「拿住这个位置」「有肉可吃」）；
  ② 拼音/方言；③ **隐含建议**（不给动作、只给强烈倾向：「明显强于大盘，值得重点关注」）。
- 因此**词表不是唯一防线**，三层各司其职：
  ① **素材约束**（第一道，也是最强的一道）：模型只看得到确定性素材、无自由输入；
  ② **词表守卫**（最后一道确定性闸）：已知变体一律拒答；
  ③ **人工可核验**：素材逐项展示，用户能发现解读与数据不符。
- 任何「守卫充分」的说法都不成立。后续若开放自由提问，必须先补第三道闸（用户输入规则拦截）。

## 后果

- 素材范围受限于云端上报体（无评分分解/资金流），解读深度有边界——接受，
  宁可解读浅也不为此扩 Python 上报链路。
- 素材**跨表拼装**（快照按轮、K 线按票）已由「禁止」改为「允许 + 双侧轮次披露」
  （审查 A / P2-2）：`generatedFrom` 同时给快照轮次与该票 K 线最新交易日。
