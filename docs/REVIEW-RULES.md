# Code Review Rules

审查目标：**分析核心功能是否存在逻辑缺陷和 bug**。非风格/lint 审查。

## 审查范围

按优先级排序：

### 1. 数据流完整性

- **fetch → filter → score → rank → display** 全链路数据是否一致传递
- 数据源返回异常格式时（空列表、None 字段、类型不符），下游是否安全处理
- DB 读写是否可能丢失或重复数据（并发写、事务边界）
- `ScanResult` / `Candidate` / `KlineSummary` 等数据合约是否被正确构造和消费

### 2. 边界条件

- 空数据：无候选、无 K 线、无成交、零市值、零换手率
- 极端值：涨停/跌停、连续一字板、新股上市首日、ST 股
- 时间边界：开盘/收盘瞬间、午休、节假日前后、跨日
- 数值溢出/精度：浮点累加误差、除零、负数开方

### 3. 评分与分类逻辑

- 5 个策略桶的分类条件是否有重叠或遗漏
- 加成/扣分叠加顺序是否影响最终排名（非交换性）
- `ranking.py` 分档逻辑与 `analysis.py` 评分逻辑是否对齐
- `--rescore` 历史重跑是否与实时管线行为一致

### 4. 并发与时序

- 并发获取（kline_fetch / intraday_fetch）是否正确处理超时和部分失败
- 主循环 sleep 间隔与数据刷新频率是否匹配
- 排名快照是否在正确的时间点持久化

### 5. 状态管理

- 内存状态（rank_history、appearances）与 DB 持久化是否一致
- 数据源切换（雪球→同花顺）时状态是否正确迁移
- `backfill_outcomes` 回填逻辑是否覆盖所有历史记录

### 6. 指标计算正确性

- RSI / KDJ / MACD / BOLL / ADX 等技术指标公式是否正确
- 均线对齐逻辑（5/10/20/60日）是否考虑了数据不足的情况
- 成交量比、换手率等派生指标的分母是否可能为零

## 审查输出格式

对每个发现的问题，输出：

```
文件:scanner/xxx.py:行号
问题类型: 逻辑缺陷 / 边界未处理 / 数据不一致 / 潜在崩溃
描述: 简要说明
影响: 低 / 中 / 高
修复建议: 具体修改方向（不执行修改）
```

仅报告**实际或高度可能**的缺陷，不报告风格问题。
