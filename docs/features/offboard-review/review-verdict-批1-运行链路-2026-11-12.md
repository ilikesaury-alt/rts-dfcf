## 二、法官裁决（四档处置）

### ✅ 误报（反证推翻）

**B-1「flow_sum 每轮刷新 ⇒ 信号时刻读数不可复盘」—— 大部分推翻，残留降级**

反证：`OFFBOARD_FLOW_WINDOW` 窗口只含**已收盘**交易日（`offboard_flow.py:105` 的 `date < as_of`）。
同一天内，窗口成员日不变、成员日的主净额是收盘快照（不再变）⇒ **当日所有轮次算出的
flow_sum 完全相同**。实测：`SZ301020` 盘中读 = 2200352，与库里的"末轮值"一致；
`SZ301512` 同（12889648 = 12889648）。

⇒ "每轮刷新"刷新的是**同一个值**，末轮值 = 首轮值 = 信号时刻值，B 担心的错位在当前
实现下不存在。

**残留（降为低）**：唯一会改变读数的是**查询失败轮**——某轮 `load_flow_history` 抛
sqlite3.Error ⇒ `_load_flow_sums` 返回 {} ⇒ flow_sum=None、flow_judged=0 覆盖早前的正确值。
影响面小（失败轮罕见、次日窗口滑动后自然重算），且跨日后窗口滑动本来就会更新值。
**处置：接受风险**——若日后窗口改为含当日盘中数据，此条自动升级为中，需补 first_flow_sum。

**A-5「bias=None 公共面陷阱」—— 部分推翻**

反证：`bias` 形参只在 `unified_scanner.py:644` 一处被显式传值，且传的是 `_BIAS_UNSET`
或 `_bias_box[0]`（只可能是哨兵或 float）。**没有任何调用方会传裸 None**。
"未来调用方按 Python 惯例传 None"是推测，不是当前代码的反例。
但 A 指出的**机制风险**成立：哨兵语义确实反直觉，值得留一条防御线。
**处置：修复（低成本）**——在 `biased_snapshot` docstring 已有警示的基础上，把
`onboard_anomaly` 收到显式 None 时的行为（整段留空）改为告警日志，让静默变可见。

### 🔧 修复

**A-2「reason_code 是跨模块手抄文案契约」—— 真问题，修复**

核验确认：`K线未补取` 前缀在 `offboard_watch.py:1752` 有生成点（A 的 grep 漏了，不是死规则），
但"规则表命中两个模块的文案串"这一结构性风险成立——改文案一字 ⇒ 该门落 unknown ⇒
聚合静默失效。守卫测试 `test_reason_codes_cover_every_gate_branch` 是唯一拦截，
且它依赖 `_REASON_RULES` 与生成点同文件——display_gates.py 的 4 条文案（ST/市值/价格/流出）
在另一个模块，测试通过真跑门覆盖了它们 ✓。

**修复动作**：不改架构（A 自己的简化方案"门函数直接返回 (code,value)"会破坏
单测断言子串的契约，收益不抵改动面），在 `_REASON_RULES` 顶部加一条注释 +
守卫测试补 display_gates 4 条文案的显式断言（已有真跑门覆盖，补注释即可）。
**实质动作：无代码改动，补文档。**

**B-3「CLI launch_log 写表噪音未消」—— 真问题，修复**

核验确认：`_cli_conn`（:2114）已建 `_OFFBOARD_LAUNCH_LOG_DDL`……等一下，
它在列表里。**复核结果：B 报错了**。`_cli_conn` 第一步就建了 launch_log（:2114），
B 说"无 launch_log"与代码不符——这是两报告唯一的**事实性互斥**，
按汇总规则第 4 条二次核验：`grep -n "_OFFBOARD_LAUNCH_LOG_DDL" scanner/offboard_watch.py`
⇒ :2107 import、:2114 execute。**B-3 误报**。
（B 的证据 `offboard_watch.py:2110-2133` 行号偏移了，可能看的是格式化前的旧版本。）

**A-1「_CLI_READONLY_DDL 与生产 schema 漂移」—— 真问题，但影响面降级**

核验确认：生产库 `appearances` 有 `UNIQUE(symbol,date)` autoindex、`recommendations`
有 6 个 NOT NULL 列，手抄版都没有——**漂移属实**。但 CLI 路径对这五张表**只读不写**
（读侧走 SELECT，无 ON CONFLICT）⇒ 漂移当前无触发路径。A 给的反例
（"将来对这两表做 ON CONFLICT 写入"）是假设性的。
**处置：接受风险 + 到期条件**——注释已声明"改 schema 后需重新导出"；
到期条件 = 任何一次对这些表的写路径引入时，必须先跑一遍 CLI 真路径验证。
不修（共享常量重构改动面大，收益是纯假设性的）。

**B-2「persist_round 与 save_offboard_rejections 无共同事务」—— 真问题，接受风险**

核验确认：两个独立 commit。但脏状态方向是"**少留痕**"而非"错值"（fail-open 设计使然），
且 rejections 的 first_* 冻结锚在**首次被拒轮**写入，与 launch_log 首次产出的对齐
只在"同轮同时写"的理想情形下严格成立。当前唯一消费方是事后人工复盘（容忍两侧轮数不等）。
**处置：接受风险**——共同事务（BEGIN IMMEDIATE 包两表）改动面涉及 dal 层接口，
收益是复盘严谨性提升；列为下一轮 observe-first 复盘时的候选改进，不急。
