# rts-desktop · 正式视觉设计重做规格

> 版本：v2.0 · 方向修正（有温度的精致） · **纯表现层规格，零契约改动**
> 适用：Windows 桌面应用 `rts-desktop`（创业板飙升榜 · 本机只读看板），基准视口 1600 × 900
> 交付：`DESIGN.md`（本文）+ `preview.html`（自包含可交互预览，含列表 / 个股详情、折叠记忆、分段滑块与多态状态）
> 本文件只提出设计与后续实施边界；**本次不修改任何生产代码**。

## v2 方向修正说明

> 用户看完 v1 后反馈：**「我需要一个交互友好，看着美的 ui」**。v1 的「Bloomberg / Linear 式克制冷峻专业终端」定位被否决：近全灰、字号集中在 11~12px、卡片与底色几乎无对比，冷得像调试器。本次修正为 **「有温度的精致 · 好看且交互舒服」**：引入克制青蓝品牌色、让卡片表面浮起、拉开字阶，并把导航跳转/跟随、折叠记忆、行 hover 进详情、分段滑块、多态状态解释、键盘可达与 reduced-motion 全部做进 `preview.html`。硬纪律一条未放宽：仍是只读镜像，`SCHEMA_VERSION=2`，A 股红涨绿跌与数据契约不动，本次仍不改任何生产代码。（**v3 注**：2026-11-16 Lichun 反馈「不要黑色主题，重新设计」，配色已由暗底转为浅底。仅配色/表面/阴影层变更，交互与数据契约一字未动。）后文若与本节冲突，**以本节与「交互规格」为准**；与方向无关的既有章节保留。

## 1. 设计定位与原则

> **定位一句话：** `rts-desktop` 是一块**有温度、能顺手探索的本机只读看板**——先用清晰的轮次与关键读数建立信任，再用舒展而不松散的表面、明确的交互反馈，让人舒服地读表、定位区块、查看个股；它只改变「怎么看」，不改变「有什么」。

### 设计原则（5 条）

1. **美来自秩序，不来自装饰堆叠。** 主色只用一个青蓝品牌色 `--brand: #4c8dff`，辅色用更淡的 `--brand-soft: #22d3ee`；它们负责应用标识、选中态色条、分段滑块、状态点、焦点环和极淡的标题栏光晕。**浅色为唯一形态**（v3：2026-11-16 由暗转浅；不引 dark mode、不引主题切换）。渐变只允许两处：标题栏品牌光晕、选中/滑块的细微过渡；不铺满屏、不做玻璃拟态、不做发光边框、不做大圆角彩色卡片。
2. **表面要「浮」起来，信息密度仍守住。** 背景 `#0c131e` → 卡片 `#141e2d` → hover/选中 `#1c2a3e` → 弹层 `#243650`，四级表面逐级抬亮。卡片用 9~10px 圆角、`1px` 顶部内高光 `inset 0 1px 0 rgba(255,255,255,.055)`、一层极淡阴影；卡片间距/内边距比 v1 舒展一档（18px / 15~16px）。表格行高仍约 **28px**（**v4 修订为 30px**，见末尾 v4 章节），不变成消费级大留白，不加 KPI 墙或图表墙。
3. **字阶是一眼看懂层级的最短路径。** 应用名 15~16px semibold、区块主标题 14~15px semibold、关键读数 20~24px tabular-nums、表头 11px、口径说明 11px dim + 1.55~1.65 行高、数据行 12~13px tabular-nums。不再让标题、读数、表头、口径、页脚挤在同一灰阶和同一字号里。
4. **交互反馈要被看见，也要能退场。** 所有可点元素都有 hover / focus-visible / active 三态，过渡统一 120~160ms ease（预览采用 140ms）；hover 只抬亮表面与文字，active 仅 1px 下沉，不做位移卡片、不做整行闪烁。`prefers-reduced-motion: reduce` 时动画与平滑滚动退场，状态与内容不丢失。
5. **只读忠实地呈现，包括「空」。** 空区块用纯 CSS 图形、口径说明和终端同源 `—（本轮无数据）` 组成完整版面，不编造原因、不补写行、不把 `—` 改写成 `0`。页脚写数据来源、轮次与口径；所有交互只改变导航位置、展开状态或列表/详情视图，不新增筛选、排序或任何结论。

### 参考取向（只借组织与手感，不抄外观）

专业交易终端：紧凑表格、高密度数字、状态与轮次常驻、红涨绿跌；现代桌面工具：清晰表面层级、可读中文小字、强选中态、顺滑但仍干脆的 120~160ms 反馈、明确的键盘焦点。**明确拒绝**：v1 的近全灰调试器感、满屏渐变、玻璃拟态、发光边框、仪表盘式大数字卡阵列、装饰性 icon 墙、消费级大留白。

## 2. 硬纪律（写进规格，实施时逐条验收）

1. **面板是终端的只读镜像（G5）**：不新增筛选、不新增排序、不新增结论/建议/综合判断。预览与正式 UI 均不得出现「推荐 / 建议 / 应该买 / 综合判断」等结论性文案。现有「临时排序」若保留，仍限于既有白名单且显式标注；本次**不扩展**。
2. **列头单源**：列头只来自服务端下发 `colSpec`；`components/**` 不得写死列名。表格仍由 `RegionTable` 渲染 `spec.label`，行尾 `新 / ⚡ / 稳 / ▼` 标记仍在 `colSpec` 之外的窄列，不并入任何数据列。预览稿的列名是**静态设计示意**，不是生产代码。
3. **数据契约零改动**：`SCHEMA_VERSION = 2`，`api/types.ts` ⇄ `panel_serialize.py` ⇄ `worker/src/serialize.ts` 三端镜像不动；不新增字段、不新增请求、不改 `client.ts` 唯一网络收口。所有新数字只能来自已有 `snapshot.regions` / `snapshot.ctx` / `gate.stats` 的展示重组，且不得重算业务口径。
4. **A 股语义同源**：红涨 `#ef232a`、绿跌 `#14b143`；空值显 `—`；`新`（本轮新进池）/ `⚡`（动量加速）/ `稳`（日线美感）/ `▼`（主力净流出警示，用警示色而非跌色）语义与终端同源。涨跌色不得用于普通选中态或导航态。
5. **浅色是唯一形态**（v3，2026-11-16 由暗转浅）：不引 dark mode、不引主题切换；预览稿允许记录视图偏好，生产落地沿用既有分栏宽度键、不扩张成状态库；`pages/Stock.tsx` 的 `ASHARE_THEME` 仍与 CSS token 持有同一组涨跌字面值，改色必须两处同步。

## 3. 视觉语言

### 3.1 表面、色板与品牌色边界

| Token | 色值 | 用途 | 表面关系 |
|---|---|---|---|
| `--surface-0` | `#070B12` | 窗口壳、标题栏、侧栏、页脚 | 最暗，负责收边 |
| `--surface-1` | `#0C131E` | 主区与右栏工作区 | 工作画布 |
| `--surface-2` | `#141E2D` | 卡片、表身 | 卡片实体感，明显浮于画布 |
| `--surface-3` | `#1C2A3E` | 卡片 active header、hover 行、选中导航、分段槽 | 交互抬亮 |
| `--surface-pop` | `#243650` | 状态解释弹层、active 按压 | 最高表面，仅小面积 |
| `--line-soft` / `--line` / `--line-strong` | 白 7.5% / 12% / 20% | 内分隔 / 卡片边框 / 表头与冻结列 | 1px 结构线 |
| `--text-1` / `--text-2` / `--text-3` / `--text-4` | `#F2F6FC` / `#B9C5D6` / `#8D9CB0` / `#64748B` | 主标题与读数 / 数据 / 口径与表头 / 非信息字符 | 四级灰阶，弱文本仍可读 |
| `--brand` | `#4C8DFF` | 应用标识、选中色条、滑块主色、历史快照点、焦点环 | **只做交互/身份，不编码涨跌** |
| `--brand-soft` | `#22D3EE` | 副名、关键通过读数、门内计数、本轮新鲜点、查看提示 | 品牌辅助色，同样不编码涨跌 |
| `--up` / `--down` | `#EF232A` / `#14B143` | 涨 / 跌 | **数据专用色**，仅数值与 K 线数据语义；不与品牌色混用或替换 |
| `--amber` / `--coral` | `#F5BB63` / `#FF7B8E` | 滞后 N 轮 / 服务无响应 | 状态语义，配文字说明，不占用涨跌色的语义位 |

> 卡片：`background: var(--surface-2)` + `1px solid var(--line)` + `border-radius: 10px` + `inset 0 1px 0 rgba(255,255,255,.055)` + `0 9px 24px rgba(0,0,0,.20)`。只用一层浅阴影帮助表面分离；hover 把边框抬到 `rgba(76,141,255,.22)`，不做发光。弹层比卡片再亮一级，自带顶部内高光。

### 3.2 字阶（数字一律 tabular-nums）

| 级别 | 字号 / 行高 / 字重 | 用途 |
|---|---|---|
| `app-title` | 15~16 / 20 / 650 | 产品名；副名 10px / 650 / 0.12em 字距用 `--brand-soft` |
| `section` | 14~15 / 20 / 650 | 区块主标题、卡片主标题、详情主标题 |
| `readout` | 20~24 / 26~28 / 650 `tabular-nums` | 首屏关键读数 `池选 10` / `过门通过 6`、过门三项账目；仅有限几处，不做 KPI 墙 |
| `data` | 12~13 / 18 / 500~600 `tabular-nums` | 表格数据；代码列等宽 11.5px |
| `table-head` | 11 / 16 / 650，字距 0.025em | 表头（生产 UI 仍只取 `spec.label`） |
| `meta` | 11 / 1.55~1.65 / 450~550 | 口径说明、轮次、状态副行、空态说明、页脚；dim 但行高舒服 |
| `micro` | 10~10.5 / 14 / 600~650 | 徽章、段标签、状态副行、终端同源 `—（本轮无数据）` |

字体栈：`"Inter", "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif`；数字/代码：`"JetBrains Mono", "Cascadia Mono", Consolas, monospace`。全表 `font-variant-numeric: tabular-nums lining-nums;`；涨跌数字保留符号与两位小数，列右对齐；代码/名称/板块左对齐；标记列定宽并容纳淡入的「查看 →」。

### 3.3 间距、圆角、分隔与两处渐变

- 基础节奏 4px；主区内边距/卡片间距 **18px**；卡片 header 内边距 11~15px；主区、右栏、侧栏各自 `min-height: 0`，只让内容区滚动。
- 表格行高 **28px**（**v4：30px**）**、表头 29px→v4 31px**，单元格左右 10px；冻结首列保持，滚动时右沿 1px 强线；不使用斑马纹。
- 圆角：卡片 **10px**；导航项、按钮、徽章、分段槽、空态图形 7~9px；弹层 10px。圆角是「舒展一档」，不是 ≥16px 消费级胶囊卡片。
- 卡片 header 与 body 之间 1px soft 线；卡片 hover 边框可微微转青蓝；焦点环 `2px solid var(--brand)` / `offset 2px`，表格行内缩 `-2px`。
- **渐变白名单只有两处**：① 标题栏左侧非常淡的径向品牌光晕（约 13% 透明度，不覆盖文字，不铺满标题栏）；② 门内/门外滑块从 `--brand` 到 `--brand-soft` 的 100deg 细微过渡。其余位置一律纯色表面；背景网格线不是渐变，不属于装饰。

### 3.4 动效（只服务反馈，140ms 为默认值）

| 交互 | 动效 | 约束 |
|---|---|---|
| hover / focus / active | 背景、边框、文字色、轻微 1px 下沉：120~160ms ease；焦点环即时可见 | 无卡片位移、无发光、无缩放 |
| 分段滑块 | `transform: translateX(100%)`，150ms ease；面板内容即时切换 | 账目区与标题不重排 |
| 卡片折叠 | `grid-template-rows: 1fr → 0fr` + 透明度，150ms ease | 折叠后内容 inert / `aria-hidden`，不参与 Tab |
| 导航滚动 | 预览使用 150ms 缓动滚动；生产沿用既有 `scrollTo`/`useActiveSection` 的踩坑结论 | 用户点击后短暂锁定滚动跟随；reduced-motion 直接定位 |
| 状态解释弹层 | 140ms 淡入 + 4px 下沉 | 不是 toast，不自动消失；Esc / 外部点击关闭 |
| 首次载入 | 无入场动画、无骨架假数据 | 刷新后按 hash 恢复列表/详情 |
| 新轮次到达 | 仅读数颜色短暂过渡 | 不整行闪烁、不常驻呼吸效果 |

## 4. 应用外壳与逐屏布局（v2 框架口径）

> 本节只保留外壳约束的框架；具体尺寸、表面、字阶与组件形态以 §1 / §3 / §5 / §7 为准，旧版 40px / 72px / 8px 圆角 / 18px 读数等数字不再作为验收值。若后续 P2 改 `desktop/**`，仍按 §9 的分期与风险单独验收。

- **单一应用身份**：表面色连续到窗口边缘；P0 的窗口内品牌标题栏与 P2 的 frameless 自定义标题栏只能二选一，不同时留 OS 双头与两套窗口控件。Windows 任务栏 / Alt+Tab 仍保留 `title`；窗口级操作若落地，仍走三个白名单 IPC，`contextIsolation / nodeIntegration / sandbox` 安全基线不动。
- **稳定的四段高度链**：48px Title → 76px Readout → `flex:1; min-height:0` Workspace → 40px Footer。Workspace 内主区与右栏各自滚动，不滚 `window`；沿用 `Panel` 内层 `min-h-0` 与既有滚动踩坑结论。窄视口整体缩放，不改成移动版。
- **三列工作区**：侧栏 208px（可折叠到 64px）→ 主区弹性宽度（18px 内边距与卡片间距）→ 右栏 386px；既有分栏宽度持久化与拖动比例约束在生产落地时保留。详情视图沿用同一个壳，隐藏侧栏与右栏，避免「单只股票」与「本轮卡片集合」两种口径混屏。
- **读数带只放已有轮次事实**：`池选 10` / `过门通过 6` 用 20~24px tabular-nums；完整轮次 `2026-10-19 16:41:20 · seq 99 · 非交易时段`、本机回环与 `seq 99` 保持可读；不派生指标、不放 KPI 卡墙。切到详情时，中段换成 `个股 / 代码 / 名称` 与返回动作。
- **页脚是产品语言**：`数据来源：本机扫描器最后一轮快照 · 本机回环 127.0.0.1 · 每 60s 读取一次 · 轮次、时段与区块口径随快照呈现 · 数据版本 v2`；不写内部纪律宣言，不出现筛选/排序判断词。
- **状态判定不变**：生产态仍按已有 `meta / snapshot / error / sessionLabel / lagRounds` 五类信息映射，非交易时段的「历史快照」优先于交易时段的「滞后 N 轮」；v2 只替换视觉、解释弹层与交互，详见 §5.4 / §7。

### 4.1 Electron 原生标题栏如何取舍（实施约束，沿用）

**目标形态：单一自定义标题栏（frameless）。** P2 落地时把 `desktop/main.js` 的 `BrowserWindow` 设为 `frame: false`（Windows 同时保留 `title` 供任务栏/Alt-Tab），由渲染层提供可拖拽标题栏；窗口级操作区为 `no-drag`，通过受控的 `ipcRenderer.invoke('window:minimize|maximize|close')` 调到主进程 `win.minimize() / win.isMaximized() ? restore() : maximize() / win.close()`。主进程白名单只收这三个动作，不暴露通用 IPC；仍保留 `contextIsolation: true` / `nodeIntegration: false` / `sandbox: true`，通过受限 `preload` 暴露三个方法即可。**不要**用 `titleBarStyle: 'hidden'` + OS 保留的拖拽热区混搭。P0/P1 预览稿只做窗口内品牌身份条，不画假窗口按钮、不假装有窗口行为。

## 5. 关键组件形态

### 5.1 卡片与折叠

```
┌──────────────────────────────────────────────────────────────────┐
│ ▌v1 池选  [主线]                    10 本轮行  [⌄]              │ 58px
│   v1 池选 — 新票优先·类别优先·排名升序·资金流降序                │
├──────────────────────────────────────────────────────────────────┤ 1px
│ 表头 31px / 10 行 × 30px / 冻结首列 / hover 整行 + 查看 →       │
└──────────────────────────────────────────────────────────────────┘
```

卡片是 `--surface-2` 的浮起表面、10px 圆角、顶部内高光与一层极淡阴影；header 在选中时抬到 `--surface-3`，左侧 3px 品牌色条。右侧槽位包含 `本轮 N 行` 徽章与折叠按钮；折叠按钮不是筛选/排序控件，只改变当前区块的展开状态，状态写进 `localStorage`，折叠后内容 inert / `aria-hidden`。空态卡片沿用同一骨架，不因有没有数据改变卡片身份；卡片间距 18px，间距舒展但表格密度不放大。

### 5.2 表格与个股入口

- 列头仍视为服务端下发（预览照抄给定列名，不新增、不改名、不加排序箭头）；表头 11px，数据 **13px**（v4）tabular-nums，行高 **30px**（v4）。红涨绿跌只用 `#ef232a` / `#14b143`；`—` 用次级色但保留等宽占位；行尾 `新 / ⚡ / 稳 / ▼` 语义与终端同源，标记列定宽 112px。
- 行 hover：整行底色 `--surface-3`，右侧「查看 →」在 140ms 内淡入并轻微右移到位；active 抬到 `--surface-pop`；focus-visible 用内缩焦点环。整行是 `role="link" tabindex="0"`，点击 / Enter / Space 进入个股详情，URL 变为 `#/stock/<code>`。
- 详情视图沿用同一标题栏、读数带与页脚；读数带中段换成 `个股 / 代码 / 名称`，`返回列表` 按钮与 `Esc` 都回到 `#/list` 并把焦点还给来源行或门内按钮。刷新、前进/后退都按 hash 恢复，不乱跳。
- K 线用**排版成品级、但明确无行情数值**的占位：主图网格、占位柱块、成交量副图、时间轴、图例与 `—` 轴标签；不写日期、不写价格、不写 MA 数值，避免把布局占位误读为假数据。右侧「本轮字段」只展示该股在给定快照里的字段；「出现史」用同一套空态语法，不补写历史。

### 5.3 空态（有设计，不编造）

- 区块空态 136px：纯 CSS 画出的 58×48 小方框（顶部基线、三段虚化行条、中间 `—`），不引外链图片；右侧 13px 主句 `本轮无数据` + 11px / 1.65 行高的口径说明；右下角保留 `—（本轮无数据）` 10.5px。
- 段空态 90px：同图形缩到 44×37，段标题仍保留；两段各自独立，口径句写「该段在本轮口径下没有行；两段并列、互不排名。」，不改段标题、不写原因猜测、不显示 0、不渲染空表头。
- 详情「出现史」沿用空态语法，主句/口径/终端标记三件齐全。所有空态都不出现「稍后再试」「市场清淡」「扫描器没抓到」之类推断，也不出现任何结论词。

### 5.4 状态指示（多态 + 可解释）

| 状态 | 文案 | 视觉 | 点击展开的一句解释 |
|---|---|---|---|
| 本轮新鲜 | `本轮新鲜` / `seq 99 · 16:41:20` | `--brand-soft` 点 + 淡青环 | 当前显示本机扫描器最近一轮快照；轮次、时段与 seq 保持原值。 |
| 滞后 N 轮 | `滞后 N 轮` / `显示最后一轮快照` | 琥珀点 + 琥珀描边 | 轮次间隔超过一轮时，画面保留最后一轮快照与 seq 原值。 |
| 历史快照 | `历史快照 · 非交易时段` / `2026-10-19 16:41:20 · seq 99` | `--brand` 点 + 青蓝环，中性信息态 | 非交易时段展示最后一轮历史快照；轮次、时段与 seq 按快照原值呈现。 |

### 5.6 侧栏导航

宽 208px（折叠 64px）；每项 44px，图标 + 13px 文字 + 右对齐行数徽章（空区块显 `—`），选中态是 `--surface-3` 表面 + 左侧 3px 品牌色条 + 文字提亮三重信号。点击导航滚动到对应区块并立即高亮；主区滚动时高亮跟随，点击后的短暂锁定避免滚动动画把高亮「拉回去」；`飞书过门` 对应右栏卡片并滚右栏到顶。折叠态只留图标，所有入口保留 `title` 并自绘右侧 tooltip，不再用不稳定的两字缩写；折叠按钮有 `aria-label / aria-expanded`，状态持久化。底部仍是 `本机 · 只读` 与品牌色状态点。

### 核心问题：什么叫「灰盒子堆叠」

v4 结束时每个区块都是一张**白卡 + 1px 灰边 + 12px 圆角 + 遮罩投影**。十张卡片上下排列时，
读者眼里不是「十个区块」，而是「十个盒子堆在一张灰画布上」——边界靠**围合**建立，
于是每一层都在喊「注意我」，反而没有一层是主体。

**v5 的解法：把边界从「围合」换成「色差 + 分隔线」。**

| 层 | v4（盒子） | v5（纸面） |
|---|---|---|
| 卡片 | `bg #fff` + `border 1px` + `radius 12px` + `box-shadow` | `bg #fff` + **无边框、无圆角、无投影** |
| 画布 / 卡片 | 灰画布 `#f3f6fa` ↔ 白卡（靠浮起） | **同色纯白**（画布即纸面） |
| 区块边界 | 卡片边框 | 标题竖锚点 + `1px` 分隔线 + 留白 |
| 框架区（标题/读数/侧栏/页脚） | `#e3e8f0`（明显的灰壳） | `--surface-rail` 极淡冷白，靠**色差**界定 |

### 落地 token

```css
--surface-0/1/2: #ffffff        /* 框架、画布、卡片全部纯白 —— 去盒子感的关键 */
--surface-rail:  #f3f5f9        /* 框架区（见下方修正） */
--surface-3:     #f4f6fa        /* hover/选中，只在交互瞬间出现 */
--line-soft: #eef1f6  --line: #e7eaf0  --line-strong: #d9dee7
--text-1: #161b26  --text-2: #3d4658  --text-3: #6e7789  --text-4: #98a1b2
```

**牌品色、涨跌色、状态色一字未动**（`--brand #2563eb` / `--up #d9222a` / `--down #0a8f3c`）。

### ⚠⚠ 实施中踩到的坑：**「去盒子」不能连带去掉「边界」**

第一版把 `--surface-rail` 取成 `#fafbfd`，实测：

- `#fafbfd` vs 纯白画布 `#ffffff` 的对比度只有 **1.035** —— 低于肉眼可辨阈值；
- 结果 **全屏 96% 面积（4801k px）是同一片纯白**，侧栏/标题栏/页脚与内容区**糊成一整片**。
- ⇒ 「盒子感」确实没了，但同时**失去了「这是个应用界面」的框架感**：
  读者不知道左栏在哪结束、内容区在哪开始。

**修法（不是回退）**：`--surface-rail` 改 `#f3f5f9`，与白画布 **1.091**、与结构线 `#e7eaf0` **1.104**
—— 两个方向都刚好可辨，仍是极淡冷白而非灰底。**卡片依旧无边框无圆角无投影**。

> **教训（写死在这里）：「去掉装饰」与「去掉结构」是两件事。**
> 判断依据必须是**对比度算式**而不是「看起来更干净了」——
> 当一个边界只能靠装饰（边框/投影）建立时，去掉装饰就必须先给它一个**替代的结构信号**
>（色差 / 分隔线），否则你删掉的是层级本身。

### 同时修掉的一个真 bug（与本轮无关但同批）

`index.html` 的头两个 meta 是 **v3 暗色时代的残留**：

```html
<meta name="color-scheme" content="dark" />     <!-- ← 应用早已是浅色 -->
<meta name="theme-color" content="#070b12" />   <!-- ← 暗色壳色 -->
```

CSS 里有 `color-scheme: light`，但 HTML 的 meta 一直没跟着改 ⇒ 浏览器在**首帧**、
原生表单控件、滚动条上仍按暗色渲染（浅底上会闪深色控件）。
已改为 `light` / `#e3e8f0`，并接上 `favicon.png`（由新图标 256px 导出）。

**教训：换主题时「CSS 里的变量」和「HTML 里的 meta」是两套独立真源，只改一套等于只改一半。**
