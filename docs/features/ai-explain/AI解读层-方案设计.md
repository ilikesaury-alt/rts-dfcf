## 1. 一句话

在云端面板上给「这只票为什么出现在榜单里、它的信号怎么读」加一个 **AI 自然语言解读**：
解释素材由服务端**确定性函数**从已有快照组装，LLM 只负责把素材转成自然语言，
输出强制带「仅解读，非投资建议」标签，**不产生任何新信号、不入库、不参与排序与过门**。

## 2. 为什么这样做（哲学同构）

本项目 AGENTS.md 的核心纪律：系统唯一有证据的口径只有**类别先验**，短名单 / 终选 /
综合判断等「第二结论源」已全部删除。引入 LLM 最大的风险恰恰是制造第二个结论源。

health-track 已验证的解法是让 LLM **丧失产生结论的能力**，而不是「提示词求它别越界」：

| health-track 范式 | 本项目对应 |
|---|---|
| LLM 只转录原文，`value_num`/异常状态由纯函数算 | LLM 只转述素材，**一切数字与判断来自 D1 快照的确定性组装** |
| 参考范围解析不出 → 判「无法判断」，绝不猜 | 素材缺失的字段 → 明确写「暂无数据」，LLM 不许补 |
| 解读红线：只做含义/趋势/复查方向 | 只做：信号含义、类别先验解释、出现史描述；**不做买卖建议、目标价、仓位** |
| `source_quote` 对照 + 人工确认闸 | 每段解释绑定素材 ID，前端可展开素材对照 |

## 3. 架构

```
浏览器（web 面板，Access 保护）
   │  POST /api/ai-explain { symbol }
   ▼
cf-panel-api Worker
   ① 鉴权（沿用现有 Access + auth.ts）
   ② 确定性素材组装（新模块 src/explain/material.ts，纯函数）
      从 D1 当轮快照取该票：类别、tier、评分分解、资金流、出现史、类别先验命中率
      → 组装成带 ID 的素材数组（缺字段 = "暂无数据"，不猜）
   ③ LLM 转录（src/explain/llm.ts，fetch magpie，OpenAI 兼容 /chat/completions）
      system prompt：只许转述素材，禁止输出数字结论与建议动词
   ④ 红线扫描（src/explain/guard.ts，确定性词表）
      命中「建议买入/卖出/目标价/仓位/止损」等 → 整体替换为拒答文案
   ⑤ 返回 { label: "仅解读，非投资建议", text, materials[] }
   ▼
前端固定渲染标签 + 文本 + 素材对照（可折叠）
```

**关键边界**：
- Python 侧（scanner / 上报链路 / feishu / 终端渲染）**零改动**。
- AI 输出**绝不写入** `recommendations`、不进排序键、不进 `push_gate`；
  缓存若落 D1，放独立 `ai_explain_cache` 表，仅作重复请求去重，任何计算路径不读它。
- 无自由文本输入：v1 请求只有 `{ symbol }`，**没有问答面**，越界提问在结构上不存在
  （这是比「词表拦截用户输入」更强的守卫——health-track 的「规则守卫第一道闸」在此退化为不需要）。

## 4. Secrets（沿用 worker 既有纪律）

| Secret | 说明 |
|---|---|
| `MAGPIE_BASE_URL` | OpenAI 兼容网关地址 |
| `MAGPIE_API_KEY` | 网关密钥（**用户自备**，不与 fde 作品集共享凭据） |
| `MAGPIE_MODEL` | 模型名 |

全部走 `wrangler secret put`（vars 明文可读，只放 CORS 白名单——与现有 `INGEST_SECRET` 同规）。
未配置时端点返回面向用户的明确文案，**不调模型、不泄露堆栈**（对齐 fde product1 验收 7 的成熟做法）。

## 5. 成本与性能控制

- **按素材去重**：素材内容 hash 为 key，同素材命中缓存直接返回（快照轮内天然重复）。
- 快照过期（距当轮 > 阈值）→ 明确提示「基于 X 分钟前快照」，不给虚假实时感。
- 素材短（单票信号约几百 token），v1 **非流式**即可；流式（content-studio 模式）留 Phase 2。

## 6. 验收标准（写死，实现前不得放宽）

| # | 标准 | 验证方式 |
|---|---|---|
| 1 | 票不在当轮快照 → 明确 404 文案，**不调模型** | vitest 单测（mock fetch 断言零调用） |
| 2 | magpie 未配置 → 面向用户文案，无堆栈泄露 | vitest |
| 3 | 每个响应必含 `label: "仅解读，非投资建议"`（服务端保证，前端不信任自拼） | vitest |
| 4 | 红线词表：mock LLM 返回含建议动词 → 被整体替换为拒答文案 | vitest |
| 5 | 素材组装为纯函数：同一快照输入 → 素材字节级一致；缺字段输出「暂无数据」 | vitest（确定性断言） |
| 6 | AI 输出零写入 `recommendations`/排序/过门路径；`ai_explain_cache` 仅缓存读 | vitest + 现有 e2e 回归 |
| 7 | 既有回归：worker vitest 全绿；Python pytest 全量无新增失败（本应零改动） | CI |
| 8 | 前端无密钥、无堆栈泄露 | 人工审查 + 构建产物扫描 |

## 7. 风险与已知边界

- **LLM 幻觉残余风险**：素材约束 + 低温度 + 词表扫描三道闸后仍有残余（转述时添油加醋），
  靠「素材对照可核验」让人工能发现，不做自动化事实校验（Phase 2 可考虑）。
- **类别先验解释的口径来源**：先验命中率必须取自本项目自己的统计产物
  （`rule_validate` / `prevday_perf` 的基线指标随快照上报），LLM 不许用自己的市场知识补充。
  ⚠ 若当前上报载荷未含该统计，需要**扩上报字段**（这是唯一可能触碰 Python 侧的点，见 §8）。
- **成本**：magpie 按量计费，缓存 + 单票单轮一次可把量压到「人工点击才产生」。
